# advdb-activity3-Group5 — JSONB and Vector Databases

DBAD 4000 Class Activity 3. One PostgreSQL database for a media-streaming service that stores data
three ways: **structured columns**, **JSONB** (data whose shape varies), and **vectors** (pgvector,
for searching titles by meaning).

**Group 5:** Noah Jobse, Melody Shih, Altesse Imena.

## What's where

| Path | Contents |
|---|---|
| `sql/01_schema.sql` | Tables: `users`, `titles`, `activity_log` (+ the vector half adds `search_phrases`). GIN indexes on each JSONB column. |
| `sql/02_load_titles.sql` | Loads the 60-title catalogue from `data/ca3_titles.csv`. |
| `sql/03_seed_users.sql` | 24 synthetic users (JSONB preferences). |

| `sql/08_vector_queries.sql` | The three vector queries (cosine distance, `<=>`). |

| `requirements.txt`, `notebooks/`, `docs/CA3_Making_the_Embeddings.docx` | Instructor-provided files for the pgvector / embeddings step (vector half). |

## Design (why each kind of storage)

- **Structured columns** for fields we join, filter, group, or constrain on: `users.plan`,
  `users.country`, `activity_log.event_type`, the `user_id` / `title_id` foreign keys.
- **JSONB** for data whose shape legitimately varies: `users.preferences` (a `favourite_genres`
  array plus subtitle language and a parental-controls flag) and `activity_log.details`, where a
  `play` event records `minutes_watched`, a `rate` event records `stars`, and a `search` event
  records a `query` and a result count.
- **Vectors** (`titles.embedding`, pgvector) for searching title descriptions by meaning rather than
  exact words. `search_phrases.embedding` holds the vectors for phrases a viewer might type, made
  by the same model, because PostgreSQL can compare vectors but can't turn text into one.

The activity events use the **hybrid** pattern: common, queryable fields are real columns (so we keep
foreign keys and type checks); the per-type fields live in one `details jsonb` column. GIN indexes use
`jsonb_path_ops` because our only JSONB filter is `@>` containment, which that operator class serves
with a smaller, faster index.

## Setup and run

Needs Docker (or a local PostgreSQL 16 with the pgvector extension). From the repo root:

```bash
# start a Postgres that has pgvector
docker run -d --name ca3-pg -e POSTGRES_PASSWORD=ca3 -e POSTGRES_USER=ca3 -e POSTGRES_DB=ca3 \
  -p 5433:5432 -v "$PWD":/repo pgvector/pgvector:pg16

# build + load (JSONB half)
psql postgresql://ca3:ca3@localhost:5433/ca3 -f sql/01_schema.sql
psql postgresql://ca3:ca3@localhost:5433/ca3 -c "\copy titles(title_id,title,kind,release_year,genre,description) FROM 'data/ca3_titles.csv' WITH (FORMAT csv, HEADER true)"
psql postgresql://ca3:ca3@localhost:5433/ca3 -f sql/03_seed_users.sql
psql postgresql://ca3:ca3@localhost:5433/ca3 -f sql/04_seed_activity.sql
psql postgresql://ca3:ca3@localhost:5433/ca3 -f sql/05_jsonb_queries.sql

# vector half (the two notebook outputs, then the queries)
psql postgresql://ca3:ca3@localhost:5433/ca3 -f sql/06_ca3_titles_vectors.sql   # last line: 60 | 60 | 384
psql postgresql://ca3:ca3@localhost:5433/ca3 -f sql/07_ca3_search_phrases.sql
psql postgresql://ca3:ca3@localhost:5433/ca3 -f sql/08_vector_queries.sql
```

**Vector half:** the schema declares `titles.embedding vector(384)` (left NULL by `02`). It is filled
by `notebooks/ca3_make_embeddings_vscode.ipynb`, following `docs/CA3_Making_the_Embeddings.docx`
(Route B, VS Code, Python 3.12, `pip install -r requirements.txt`). The notebook embeds each title
description with **all-MiniLM-L6-v2** (sentence-transformers, 384 dimensions, unit length) and writes
two SQL files, committed here as `sql/06_*` and `sql/07_*`, so you don't need to rerun it. To regenerate
them, put `data/ca3_titles.csv` next to the notebook, Run All, and copy the files from `my_sql/`.
We kept the instructor's five search phrases and added two of our own
("a true story about the ocean", "a heist that goes hilariously wrong").

## Data

- **Titles:** 60 rows, instructor-provided (`data/ca3_titles.csv`).
- **Users (24) and activity events (120):** synthetic, generated by the seeded SQL in
  `sql/03_*`/`sql/04_*` (`setseed` makes them reproducible). Each preferences document has a
  `favourite_genres` array; the 120 events span four types (`play`, `pause`, `rate`, `search`) whose
  `details` differ.

## Sample output (vector queries)

All three use cosine distance (`<=>`): 0 means the same meaning, smaller is closer.

**Q4 Search by meaning:** the 5 titles closest to the phrase "something scary in the woods"
```
 title_id |         title         |     genre     | distance
       56 | The Woods Remember    | Horror        |    0.602
       59 | After Dark            | Documentary   |    0.638
       25 | Little Fox Detectives | Animation     |    0.648
       51 | The Missing Hour      | Mystery       |    0.666
       31 | Wild Kitchen          | Food & Travel |    0.671
```
The top match is the horror title about a whispering forest where people disappear. The next ones
match on meaning rather than words or genre: After Dark (animals at night) and Little Fox Detectives
(a woodland town) share none of "scary" or "woods" but are about night and forests. The scores are
fairly close together, which shows that a small catalogue has only a few strong matches.

**Q5 More like this:** the 5 titles closest to "Hollow Pines" (Horror)
```
 title_id |       title        |     genre     | distance
       51 | The Missing Hour   | Mystery       |    0.687
       56 | The Woods Remember | Horror        |    0.695
       28 | Glacier Station    | Mystery       |    0.704
       32 | Seven Summers      | Romance       |    0.706
       31 | Wild Kitchen       | Food & Travel |    0.714
```
Hollow Pines is about campers disappearing at a remote lake. The closest titles share that theme:
friends in a cabin with a missing hour, people disappearing beside a forest, and a scientist vanishing
from a remote base. Seven Summers (a lakeside cottage) and Wild Kitchen (the Canadian wilderness) match
on setting. Similarity comes from the descriptions, not the `genre` column, so it recommends across genres.

**Q6 Vector search plus a filter:** for user 16, titles like the last one they played, minus everything they already played
```
 because_you_watched | title_id |         title         |  genre   | distance
 Neon Drift          |       17 | Signal Lost           | Thriller |    0.612
 Neon Drift          |       20 | Office of Lost Things | Comedy   |    0.711
 Neon Drift          |       51 | The Missing Hour      | Mystery  |    0.716
 Neon Drift          |       28 | Glacier Station       | Mystery  |    0.762
 Neon Drift          |        6 | Midnight Ledger       | Thriller |    0.764
```
User 16's most recent `play` event was Neon Drift, so the query ranks the catalogue by distance to it
and drops all six titles the user has already played (an `activity_log` filter). The result is a
"because you watched" row built from structured columns, JSONB event data and vectors in one query.
