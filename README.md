# advdb-activity3-Group5 — JSONB and Vector Databases

DBAD 4000 Class Activity 3. One PostgreSQL database for a media-streaming service that stores data
three ways: **structured columns**, **JSONB** (data whose shape varies), and **vectors** (pgvector,
for searching titles by meaning).

**Group 5:** Noah Jobse, Melody Shih, Altesse Imena.

## What's where

| Path | Contents |
|---|---|
| `sql/01_schema.sql` | Tables: `users`, `titles`, `activity_log` (+ the vector half adds `search_phrases`). GIN indexes on each JSONB column. |
| `sql/02_load_titles.sql` | Loads the 60-title catalogue from `data/ca3_titles.csv`. |
| `sql/03_seed_users.sql` | 24 synthetic users (JSONB preferences). |
| `sql/04_seed_activity.sql` | 120 synthetic activity events (4 event types). |

| `requirements.txt`, `notebooks/`, `docs/CA3_Making_the_Embeddings.docx` | Instructor-provided files for the pgvector / embeddings step (vector half). |

## Design (why each kind of storage)

- **Structured columns** for fields we join, filter, group, or constrain on: `users.plan`,
  `users.country`, `activity_log.event_type`, the `user_id` / `title_id` foreign keys.
- **JSONB** for data whose shape legitimately varies: `users.preferences` (a `favourite_genres`
  array plus subtitle language and a parental-controls flag) and `activity_log.details`, where a
  `play` event records `minutes_watched`, a `rate` event records `stars`, and a `search` event
  records a `query` and a result count.
- **Vectors** (`titles.embedding`, pgvector) for searching title descriptions by meaning rather than
  exact words — added in the vector half (see below).

The activity events use the **hybrid** pattern: common, queryable fields are real columns (so we keep
foreign keys and type checks); the per-type fields live in one `details jsonb` column. GIN indexes use
`jsonb_path_ops` because our only JSONB filter is `@>` containment, which that operator class serves
with a smaller, faster index.

## Setup and run

Needs Docker (or a local PostgreSQL 16 with the pgvector extension). From the repo root:

```bash
# start a Postgres that has pgvector
docker run -d --name ca3-pg -e POSTGRES_PASSWORD=ca3 -e POSTGRES_USER=ca3 -e POSTGRES_DB=ca3 \
  -p 5433:5432 -v "$PWD":/repo pgvector/pgvector:pg16

# build + load (JSONB half)
psql postgresql://ca3:ca3@localhost:5433/ca3 -f sql/01_schema.sql
psql postgresql://ca3:ca3@localhost:5433/ca3 -c "\copy titles(title_id,title,kind,release_year,genre,description) FROM 'data/ca3_titles.csv' WITH (FORMAT csv, HEADER true)"
psql postgresql://ca3:ca3@localhost:5433/ca3 -f sql/03_seed_users.sql
psql postgresql://ca3:ca3@localhost:5433/ca3 -f sql/04_seed_activity.sql
psql postgresql://ca3:ca3@localhost:5433/ca3 -f sql/05_jsonb_queries.sql
```

**Vector half:** the schema already declares `titles.embedding vector(384)` (left NULL). To fill it,
follow `docs/CA3_Making_the_Embeddings.docx` with `notebooks/ca3_make_embeddings_vscode.ipynb`
(`pip install -r requirements.txt`). The notebook generates two SQL files: one upserts the 384-dim
title embeddings by `title_id` (so they land in the existing rows) and adds an HNSW index, the other
creates and loads the `search_phrases` table. Then the three vector queries run.

## Data

- **Titles:** 60 rows, instructor-provided (`data/ca3_titles.csv`).
- **Users (24) and activity events (120):** synthetic, generated by the seeded SQL in
  `sql/03_*`/`sql/04_*` (`setseed` makes them reproducible). Each preferences document has a
  `favourite_genres` array; the 120 events span four types (`play`, `pause`, `rate`, `search`) whose
  `details` differ.

## Sample output (JSONB queries)

```
Q1 @> containment — users who like Mystery: 7 users (2, 6, 9, 13, 16, 20, 23)
Q2 ->> + aggregate — top minutes per title: Seven Summers 308, Byte Club 273, Sweep the Nation 236 ...
Q3 jsonb_array_elements_text — most common genres: Mystery/Thriller/Documentary/Comedy/Reality/Sci-fi (7 each), Drama (6)
```
